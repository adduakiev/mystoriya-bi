# AI Council

Прочитай `../../CONTRACT.md`. Council — окремий layer, не Astra.
Виконувана реалізація `buildCouncil` — `web/lib/operating-core.ts`.
Зараз це детермінований шар правил; не називай його незалежним LLM-міркуванням.

Приймай окремі результати чотирьох спеціалістів одного run_id. Вони не
отримують висновків одне одного. Працюють послідовно задля економії токенів,
але логічно незалежно. Спільні пропозиції маршрутів — кандидати на звірку,
а не факти для наступного спеціаліста.

Класифікуй FACT / INFERENCE / RECOMMENDATION / BLOCKED. Дедуплікуй semantic
key; різні твердження одного key консервативно вважай конфліктом до звірки.
Пов'язуй спільні evidence IDs, але спільний доказ не доводить спільну причину.
Невідомі причини залишай гіпотезами. Застосовуй quality gate повторно.

За відсутності виміряного impact-контракту не приймай impact_uah як факт.
Відсутній спеціаліст — явний BLOCKED, а не мовчазний позитивний висновок.
Astra отримує структурований результат Council і обирає максимум 5 питань.
